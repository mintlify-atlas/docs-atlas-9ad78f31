---
title: "Secrets API endpoints — store and retrieve ciphertext"
description: "Full reference for all secrets endpoints: create, list, get, bulk fetch, update, delete, version history, and rollback for both dashboard and SDK auth."
---

The secrets API stores and retrieves encrypted vault items. The server never sees or touches plaintext — it receives opaque base64-encoded ciphertext and returns the same bytes verbatim. Encryption and decryption always happen client-side using the Amnesia engine.

There are two parallel sets of endpoints:

- **Dashboard endpoints** (`/v1/secrets/...`) — authenticated by session cookie plus an unlocked vault. Used by the web dashboard.
- **SDK / CLI endpoints** (`/v1/sdk/secrets/...`) — authenticated by Bearer token. Used by the SDK, CLI, and CI pipelines.

Both sets share the same handler logic and produce identical request/response schemas.

<Note>
The `nameHash` path parameter and `name_hash` body field are the HMAC-SHA256 of the secret name, computed client-side using the project's HMAC key derived from the Project Vault Key. The server never receives or stores secret names in plaintext.
</Note>

---

## Name hash encoding

`nameHash` values in URL paths accept standard base64, URL-safe base64, padded or unpadded, and percent-encoded variants. The server URL-unescapes and tries all variants automatically. Clients should use standard base64 (`=`-padded) and percent-encode the result when placing it in a URL path.

## POST /v1/secrets — create secret (dashboard)

Store a new encrypted secret. Returns `409 Conflict` if a secret with the same `name_hash` already exists in the same project and environment — use PUT to update.

**Auth:** session + vault unlocked

### Request body

<ParamField body="project_id" type="string" required>
  UUID of the project this secret belongs to.
</ParamField>

<ParamField body="environment" type="string" required>
  Target environment: `development`, `staging`, or `production`.
</ParamField>

<ParamField body="name_hash" type="string" required>
  Base64-encoded HMAC-SHA256 of the secret name. Computed client-side with the project HMAC key.
</ParamField>

<ParamField body="ciphertext" type="string" required>
  Base64-encoded AES-256-GCM ciphertext of the secret value (and any metadata) encrypted with the Project DEK.
</ParamField>

<ParamField body="nonce" type="string" required>
  Base64-encoded 96-bit (12-byte) AES-GCM nonce used for this encryption. Must be unique per encryption operation.
</ParamField>

### Response `201 Created`

<ResponseField name="id" type="string">
  UUID of the created vault item.
</ResponseField>

<ResponseField name="project_id" type="string">
  UUID of the project.
</ResponseField>

<ResponseField name="environment" type="string">
  Environment the secret is stored in.
</ResponseField>

<ResponseField name="name_hash" type="string">
  Base64-encoded HMAC-SHA256 name hash, echoed back.
</ResponseField>

<ResponseField name="ciphertext" type="string">
  Base64-encoded ciphertext, echoed back.
</ResponseField>

<ResponseField name="nonce" type="string">
  Base64-encoded nonce, echoed back.
</ResponseField>

<ResponseField name="version" type="integer">
  Version number, always `1` on creation.
</ResponseField>

<ResponseField name="created_at" type="string">
  RFC3339 timestamp.
</ResponseField>

<ResponseField name="updated_at" type="string">
  RFC3339 timestamp, equal to `created_at` on creation.
</ResponseField>

<CodeGroup>

```bash curl
curl -X POST https://api.zenv.sh/v1/secrets \
  -H "Content-Type: application/json" \
  -H "Cookie: session_id=..." \
  -d '{
    "project_id": "019612ab-cd34-ef56-ab78-cd901234ef56",
    "environment": "production",
    "name_hash": "abc123==",
    "ciphertext": "ZW5jcnlwdGVk...",
    "nonce": "dGVzdG5vbmNl"
  }'
```

```bash curl (SDK endpoint)
curl -X POST https://api.zenv.sh/v1/sdk/secrets \
  -H "Authorization: Bearer ze_production_..." \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": "019612ab-cd34-ef56-ab78-cd901234ef56",
    "environment": "production",
    "name_hash": "abc123==",
    "ciphertext": "ZW5jcnlwdGVk...",
    "nonce": "dGVzdG5vbmNl"
  }'
```

</CodeGroup>

## GET /v1/secrets — list secrets (dashboard)

List secret metadata for a project and environment. **Ciphertext is never returned by this endpoint.** The response contains only the `name_hash`, `version`, and `updated_at` for each secret. The client uses the name hashes to look up which secrets correspond to which names (using a locally held name→hash map) and then fetches ciphertext individually.

**Auth:** session + vault unlocked

### Query parameters

<ParamField query="project_id" type="string" required>
  UUID of the project.
</ParamField>

<ParamField query="environment" type="string" required>
  Environment to list secrets for.
</ParamField>

### Response `200 OK`

<ResponseField name="secrets" type="array">
  <Expandable title="SecretListItem fields">
    <ResponseField name="id" type="string">UUID of the vault item.</ResponseField>
    <ResponseField name="name_hash" type="string">Base64-encoded HMAC-SHA256 name hash.</ResponseField>
    <ResponseField name="environment" type="string">Environment the secret is stored in.</ResponseField>
    <ResponseField name="version" type="integer">Current version number.</ResponseField>
    <ResponseField name="updated_at" type="string">RFC3339 timestamp of last update.</ResponseField>
  </Expandable>
</ResponseField>

Results are ordered by `updated_at` descending (most recently updated first).

**SDK endpoint:** `GET /v1/sdk/secrets` — same query parameters and response, authenticated with Bearer token.

## GET /v1/secrets/:nameHash — get single secret (dashboard)

Retrieve a single encrypted secret by its name hash.

**Auth:** session + vault unlocked

### Path parameters

<ParamField path="nameHash" type="string" required>
  Base64-encoded HMAC-SHA256 of the secret name. URL-encode characters like `=`, `+`, `/`.
</ParamField>

### Query parameters

<ParamField query="project_id" type="string" required>
  UUID of the project.
</ParamField>

<ParamField query="environment" type="string" required>
  Target environment.
</ParamField>

### Response `200 OK`

Returns the full [SecretResponse](#post-v1secrets--create-secret-dashboard) including `ciphertext` and `nonce`.

**SDK endpoint:** `GET /v1/sdk/secrets/:nameHash`

## POST /v1/secrets/bulk — bulk fetch (dashboard)

Fetch multiple secrets by name hash in a single request. Used by the SDK to load all secrets matching a schema manifest without issuing N individual GET requests.

**Auth:** session + vault unlocked

### Request body

<ParamField body="project_id" type="string" required>
  UUID of the project.
</ParamField>

<ParamField body="environment" type="string" required>
  Target environment.
</ParamField>

<ParamField body="name_hashes" type="string[]" required>
  Array of base64-encoded HMAC-SHA256 name hashes to fetch. An empty array returns an empty `secrets` array immediately without querying the database.
</ParamField>

### Response `200 OK`

<ResponseField name="secrets" type="array">
  Array of full SecretResponse objects (including ciphertext and nonce) for each name hash found. Name hashes that do not exist in the specified project/environment are silently omitted.
</ResponseField>

<CodeGroup>

```bash curl
curl -X POST https://api.zenv.sh/v1/secrets/bulk \
  -H "Content-Type: application/json" \
  -H "Cookie: session_id=..." \
  -d '{
    "project_id": "019612ab-cd34-ef56-ab78-cd901234ef56",
    "environment": "production",
    "name_hashes": ["abc123==", "def456==", "ghi789=="]
  }'
```

```bash curl (SDK endpoint)
curl -X POST https://api.zenv.sh/v1/sdk/secrets/bulk \
  -H "Authorization: Bearer ze_production_..." \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": "019612ab-cd34-ef56-ab78-cd901234ef56",
    "environment": "production",
    "name_hashes": ["abc123==", "def456==", "ghi789=="]
  }'
```

</CodeGroup>

## PUT /v1/secrets/:nameHash — update secret (dashboard)

Replace the ciphertext and nonce for an existing secret. The server auto-increments the version number and archives the previous ciphertext before overwriting.

**Auth:** session + vault unlocked (dashboard) or bearer token with `read_write` permission (SDK)

### Path parameters

<ParamField path="nameHash" type="string" required>
  Base64-encoded HMAC-SHA256 of the secret name.
</ParamField>

### Query parameters

<ParamField query="project_id" type="string" required>
  UUID of the project.
</ParamField>

<ParamField query="environment" type="string" required>
  Target environment.
</ParamField>

### Request body

<ParamField body="ciphertext" type="string" required>
  Base64-encoded new ciphertext.
</ParamField>

<ParamField body="nonce" type="string" required>
  Base64-encoded new 96-bit nonce. Must be freshly generated — never reuse a nonce with the same key.
</ParamField>

### Response `200 OK`

Returns the full SecretResponse with the incremented `version` and updated `updated_at`.

<Warning>
Always generate a fresh nonce for every PUT. Reusing a nonce with the same AES-GCM key compromises the ciphertext.
</Warning>

**SDK endpoint:** `PUT /v1/sdk/secrets/:nameHash` — requires `read_write` token permission.

## DELETE /v1/secrets/:nameHash — delete secret (dashboard)

Permanently remove a secret from the vault.

**Auth:** session + vault unlocked (dashboard) or bearer token with `read_write` permission (SDK)

### Path parameters

<ParamField path="nameHash" type="string" required>
  Base64-encoded HMAC-SHA256 of the secret name.
</ParamField>

### Query parameters

<ParamField query="project_id" type="string" required>
  UUID of the project.
</ParamField>

<ParamField query="environment" type="string" required>
  Target environment.
</ParamField>

### Response `200 OK`

```json
{ "status": "deleted" }
```

Returns `404` if the secret does not exist.

**SDK endpoint:** `DELETE /v1/sdk/secrets/:nameHash` — requires `read_write` token permission.

## GET /v1/secrets/:nameHash/versions — version history

Return the version history for a secret. Only version numbers and timestamps are returned — archived ciphertext is never exposed through this endpoint.

**Auth:** session + vault unlocked (dashboard) or bearer token (SDK)

### Query parameters

<ParamField query="project_id" type="string" required>UUID of the project.</ParamField>
<ParamField query="environment" type="string" required>Target environment.</ParamField>

### Response `200 OK`

<ResponseField name="current_version" type="integer">
  The current active version number.
</ResponseField>

<ResponseField name="versions" type="array">
  <Expandable title="VersionItem fields">
    <ResponseField name="version" type="integer">Archived version number.</ResponseField>
    <ResponseField name="created_at" type="string">RFC3339 timestamp when this version was archived.</ResponseField>
  </Expandable>
</ResponseField>

**SDK endpoint:** `GET /v1/sdk/secrets/:nameHash/versions`

---

## POST /v1/secrets/:nameHash/rollback — rollback to version

Revert a secret to a previously archived version. The current version is archived before being overwritten, and the version number is incremented (so rollback always produces a new, higher version number).

**Auth:** session + vault unlocked (dashboard) or bearer token with `read_write` (SDK)

### Request body

<ParamField body="version" type="integer" required>
  The archived version number to restore.
</ParamField>

### Response `200 OK`

Returns the full SecretResponse reflecting the restored ciphertext and incremented version.

Returns `404` if the requested version does not exist in the archive.

**SDK endpoint:** `POST /v1/sdk/secrets/:nameHash/rollback`
